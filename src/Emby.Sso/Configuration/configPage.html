The OpenID Connect issuer, for example https://auth.example.com/application/o/emby/ . Every other endpoint is read from its discovery document.
Leave empty for a public client.
The address users reach this server on, for example https://emby.example.com . Used to build the redirect URI.
The claim matched against the Emby username. Unless automatic account creation is enabled below, the Emby account must already exist, and its authentication provider must be set to Authentik SSO.
Lets phone and TV apps sign in by sending the password to the provider directly. This path cannot perform multi-factor authentication, and needs a direct-grant authentication flow bound to the provider in Authentik. It is refused outright while "Allow plain HTTP (testing only)" is on: that combination is the only one that would have this server relay a native client's real password in cleartext, so the two settings are mutually exclusive.
Emby's web login page cannot render a custom sign-in button: the login disclaimer is displayed as plain text and the login page's styling is served as an external stylesheet, so neither can inject working script. Until a future update finds another way to surface a button, give users the bookmarkable sign-in URL shown below instead — you can also paste that URL as plain text into the login disclaimer field in Emby's server settings so it is visible on the login page.

The Authentik group a user must hold to sign in. Leaving this empty refuses EVERY single sign-on, including users who already have an Emby account and could sign in before — the browser flow refuses at the sign-in URL and native apps are refused too. Set this before you install this build over a working one, or your whole user base is locked out until you do. The server log names the reason: "no required group is configured".
The claim the group list is read from. Authentik must be configured to emit it — on the direct-grant flow too, if native sign-in is enabled. If a user's token does not include this claim, their sign-in is rejected by design; the browser shows a generic refusal, but the server log records the specific reason.
The existing Emby user whose libraries and permissions new accounts are cloned from. New accounts are never administrators, regardless of the template.
Creates an Emby account automatically for a group holder who does not have one, cloned from the template user above. This is the setting that lets the plugin create users at all.
