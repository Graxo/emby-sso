Leave empty for a public client.
The address users reach this server on, for example https://emby.example.com . Used to build the redirect URI.
The claim matched against the Emby username; preferred_username is the default and the safe choice. Emby stamps a user's provider permanently and one way, and this plugin refuses any account not already assigned to it: once somebody signs in through this plugin, their Emby password no longer works until an administrator resets that account through the API.
Lets phone and TV apps sign in by sending the password to the provider directly, a path that cannot do multi-factor authentication and that is refused outright while "Allow plain HTTP" is on.
Lets a user sign in on a TV with a one-time PIN taken from a browser sign-in on a phone or laptop, instead of a password.
Emby's web login page cannot render a custom sign-in button, so this setting reserves one and does nothing yet. Give users the bookmarkable sign-in URL shown below instead.
Tick this only if your identity provider genuinely lives on a loopback or private address, which this server otherwise refuses to fetch from.

The Authentik group a user must hold to sign in. Leaving this empty refuses EVERY single sign-on, including users who could sign in a minute ago, so set it before you install this build over a working one or your whole user base is locked out until you do.
The claim the group list is read from. Authentik must be configured to emit it, on the direct-grant flow too, or every sign-in is refused.
The existing Emby user whose libraries and permissions new accounts are cloned from. New accounts are never administrators and never disabled, so leave this one disabled.
Creates an Emby account for a group holder who does not have one, cloned from the template user above. This is the only setting that lets the plugin create users at all.
